# 收藏重构 P1 实施说明

本阶段实现本地收藏解耦，以及单条收藏上传的持久化恢复。P2 全量双向合并、P3 账号设置页人工冲突处理尚未实现。

## 已实现

- `PUT /api/v1/users/collections/{subjectId}`：先提交本地事务，未绑定直接返回；已绑定在事务外调用 Bangumi，上传失败保留本地结果。
- 返回数据为 `{"localSaved":true,"remoteSyncStatus":"LOCAL_ONLY|PENDING|SYNCED|AUTH_REQUIRED|CONFLICT","localVersion":1}`。
- 新增收藏必须带 `type`，已有收藏可以部分更新；`tags:[]`、`comment:""`、`rate:0` 支持清空。条目大类从元数据校验，不再写死动画。
- 放开远端收藏 ID 和远端时间空值，分别记录本地更新时间与成功同步时间；详情和列表统一读取 `is_private`，保留旧 `private` 列用于审计。
- 客户端列表与详情支持空远端 ID；首次评价可选择分类；保存失败前不修改已展示的评价对象。保存后按远端状态提示，列表中待同步/授权/冲突记录带提示图标。
- 再次选择相同分类也可以重新保存；不会重复增减分类数量。授权恢复后重新保存可明确发起新上传。

## P1 的持久化与重试实现

P1 暂以收藏行作为合并式待上传记录：`pending_payload` 保存尚未上传成功的字段，`remote_baseline` 保存首次上传前快照，另存绑定记录 ID、账号 UID、版本、重试时间和次数。一次本地事务同时保存内容和上传意图，不依赖客户端缓存。P2 引入完整任务/明细表时迁移这些待办，不把本阶段等同于已完成全量任务持久化。

默认服务启动 60 秒后、每轮结束 60 秒后扫描最多 20 条到期 `PENDING` 记录；指数退避最大 1 小时。应用关闭不影响待上传记录，服务重启后新工作实例重新读取数据库恢复。可通过 `anime-flow.collection-upload.initial-delay-ms` 与 `retry-delay-ms` 调整扫描间隔。

每个用户/条目使用 MySQL 连接级命名锁，覆盖本地保存、立即上传、恢复上传和旧导入写入，避免不同实例同时发送旧版本与新版本。锁在异常路径释放；连接断开由 MySQL 释放。锁连接在 HTTP 期间保持，但不持有数据库事务；部署时连接池需预留锁连接和短事务连接容量。

上传前后核对绑定身份。解绑后重新绑定会得到新的 OAuth 记录 ID，旧待上传记录不自动写入新绑定。OAuth token 刷新不改变这一身份。已经发出的 HTTP 请求无法撤回；返回结果前再次校验身份，不把旧绑定的成功结果标记为新绑定已同步。

重试先读取远端：若请求字段已达到目标值，确认成功而不重复 PUT；若已记录基线且远端相关字段变化，暂停为 `CONFLICT`。没有基线的恢复任务遇到已有且不同的远端值，同样保守暂停。远端不支持条件更新时，读取到写入之间仍有外部并发窗口，不能保证跨系统强事务。

`AUTH_REQUIRED` 与 `CONFLICT` 不自动重试。P1 可通过重新授权后再次保存收藏/重新明确提交编辑恢复；完整比较双方分类并选择最终类型的界面在 P3 实现。

## 旧全量同步的临时保护

现有 `POST /collections/sync` 在 P1 仍是 Bangumi 导入入口：不再按 `sync_time` 删除本地记录；跳过 `version>0` 的本地编辑记录，防止旧任务破坏本地收藏。它不会自动上传全部本地独有收藏，也不会生成 P3 冲突列表。

单条保存的上传恢复不受应用退出影响；旧全量导入任务的数据库持久化、关闭应用后重新发现分类冲突等完整能力仍按计划 5.4 节在 P2/P3 实现。

## 部署前步骤与限制

1. 备份收藏表，在目标库执行一次 `db/migrations/20260919_collection_local_first.sql`。本次已在独立临时 MySQL 数据库演练，未对实际 `anime_flow` 执行迁移。
2. 配套发布服务端与支持空收藏 ID 的客户端。旧客户端直接读取非空 `interest.id`，不能在仍有旧客户端使用的部署中无条件开放仅本地收藏；需按发布环境采用最低客户端版本或版本隔离策略。
3. 本阶段明确拒绝 `progress` 参数；使用已有剧集观看接口。它不是收藏分类，不将其静默忽略或推测成已看话数。
4. 不直接执行带 DROP TABLE 的 `db/anime_flow.sql`，该文件只更新结构快照。
5. 回退时保留可空字段和本地数据，停用新上传执行；不能恢复旧的同步删除逻辑或直接收紧远端 ID 非空约束。

## 验证方式

- 后端：`mvn -pl flow-client -am test`。
- MySQL 集成：提供 `COLLECTION_TEST_MYSQL_URL`（无数据库路径且以 `/` 结尾，可附查询参数）、`COLLECTION_TEST_MYSQL_USER`、`COLLECTION_TEST_MYSQL_PASSWORD` 后执行上述测试。测试创建随机前缀 `anime_flow_p1_test_` 数据库，测试后删除，只使用合成数据；账号需要临时库创建/删除权限。未设置环境变量则跳过集成测试。
- 集成测试覆盖真实迁移、Mapper JSON 标签/隐私读取、空远端 ID、新旧版本条件更新、跨连接锁、先提交本地事务再调用远端、重新创建工作实例后恢复上传。
- 客户端：相关文件 `flutter analyze --no-pub`、`flutter test --no-pub test/features/user`。
- Bangumi 写请求在测试中替换为 mock，未对真实账号进行收藏写入。
